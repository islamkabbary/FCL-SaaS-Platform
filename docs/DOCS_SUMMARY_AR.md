## 0) المشروع في دقيقة

- **المنتج:** منصة **Multi-Tenant SaaS** لشركات الشحن (Freight Forwarding). كل شركة = **Tenant** ليها **قاعدة بيانات منفصلة** و**Subdomain** خاص بيها (مثلًا `acme.localhost`).
- **أول منتج تشغيلي** هيتبني فوق المنصة: **FCL Ocean Import في مصر** (استيراد حاويات كاملة بحرًا)، من الـ Pre-Alert لحد التسليم وإرجاع الحاوية الفاضية والإغلاق التشغيلي والمالي.
- **القرار الاستراتيجي:** نخلّص طبقة **إدارة الـ SaaS** الأول (الشركات، الموظفين، الصلاحيات، الاشتراكات، الدعم الفني، الأمان)، وبعدين نبدأ **FCL Operations**.
- **التقنيات:** Laravel 13 + Livewire 4 + Flux UI + Fortify + MySQL + `stancl/tenancy` + `spatie/laravel-permission` + Pest.

# الجزء الأول: طبقة الـ SaaS Management

## 2) `FCL_SaaS_Complete_Project_Handover_2026-10-19.md` — سجل المشروع الكامل

ده أكبر ملف في الفولدر، ومكتوب بالعربي المصري. اتعمل علشان أي حد (مطور جديد، جهاز جديد، حساب AI جديد) يفهم المشروع من غير ما حد يعيد الشرح. فوقه تحديث بتاريخ 20 أكتوبر بيقول إن M5 و M5.1 خلصوا.

**أهم اللي فيه:**

- **نموذج الـ Tenant والفروع:**
  - كل شركة Tenant، وليها Database خاصة (`fcl_tenant_<uuid>`)، وفيه Central DB منفصلة (`fcl_central`).
  - الفروع (Branches) **جوه** الشركة، مش Tenants منفصلة. كل شركة بيتعملها فرع افتراضي `MAIN` تلقائيًا، وممنوع حاليًا تعمل فروع زيادة.
  - كل موظف ليه **Primary Branch واحد**.
  - إنشاء الشركات **يدوي بس** من الـ Platform Admin (مفيش تسجيل عام).
- **3 حالات مستقلة لازم متتخلطش:**
  1. **Provisioning Status:** `pending → provisioning → ready` أو `failed`.
  2. **Manual Suspension:** إيقاف إداري من الـ Platform Admin.
  3. **Subscription Status:** فيه اشتراك ساري ولا لأ.
  - تفعيل الاشتراك **مش بيلغي** الإيقاف، والإيقاف **مش بيمسح** أي بيانات.
- **نموذج الاشتراك:**
  - خطط ثابتة، **سنوية بس**.
  - السعر = **Annual Base Fee + (عدد المقاعد × سعر المقعد السنوي)**.
  - كل مستخدم نشط بياخد مقعد، **والـ Tenant Admin محسوب**.
  - زيادة المقاعد في نص السنة: طلب من الـ Tenant Admin → موافقة الـ Platform Admin → حساب **Proration** لحد تاريخ التجديد.
  - تقليل المقاعد بيبدأ **من التجديد الجاي**، ومفيش Refund.
  - الدفع يدوي، ومفيش Payment Gateway. السعر `$10/user` كان **مثال بس** مش سعر معتمد.
- **الـ Support Impersonation:** دخول دعم فني مؤقت ومقيد ومسجل، مش صلاحية دايمة.
- **رحلة المشروع** من فكرة FCL لحد M4، وكل Milestone بالـ Commits بتاعتها.
- **قواعد العمل مع Claude Code و Git** (اتنقلت لـ `CLAUDE.md`): Milestone واحدة في المرة، Docs بعد كل Milestone، Commits منطقية على `main` باسم Islam Kabbary، بدون AI Attribution، **بدون Push إلا بإذن**.
- **القرارات التجارية المفتوحة:** الأسعار الحقيقية، الضرائب، الفواتير القانونية، فترة السماح (Grace Period)، سياسة التجديد المتأخر، الشركات القديمة (Legacy)، أدوار الـ Platform Admin، 2FA.
- **تصور أولي لـ FCL** (Modules مقترحة، رحلة شحنة مبدئية، وحاجات مؤجلة زي LCL و Export و Air و ERP).
- **قائمة قرارات "متتفتحش تاني"** (§19)، وده من أهم الأجزاء.

> **ملحوظة:** أجزاء كتير في الملف ده (زي §9 عن M5) اتكتبت قبل ما M5 تخلص، فبتقول إنها "غير مؤكدة". التحديث اللي فوق الملف هو الأحدث.

## 3) Milestone 1 — SaaS Foundation (`MILESTONE_01_SAAS_FOUNDATION.md`)

**الهدف:** بناء أساس الـ Multi-Tenancy بس، من غير أي وظيفة FCL.

**اللي اتعمل:**
- **المنصة المركزية** على `localhost:8000` وقاعدة `fcl_central`.
- **Platform Admin** بـ Guard وجدول ولوجين منفصلين (`platform`)، مع Rate Limiting (5 محاولات).
- تثبيت `stancl/tenancy` v3.10.1 بنظام **Database لكل Tenant**، والتعرف على الشركة من الـ **Subdomain**.
- **فصل الـ Routes:** `routes/web.php` للمركز، و `routes/tenant.php` للشركات.
- **الـ Provisioning** (`ProvisionTenant`): سجل الشركة → إنشاء الـ DB → Migrations → فرع `MAIN` → أول Tenant Admin → `ready`. لو فشل يبقى `failed`، والأمر `tenants:provision` بيكمّل من غير ما يمسح حاجة.
- **أول Tenant Admin** بياخد Password مؤقت عشوائي بيظهر **مرة واحدة بس**، ولازم يغيره في أول دخول.
- التسجيل العام مقفول، والـ Tenant Admin ممنوع يعمل فروع.
- مستخدم MySQL مخصوص `fcl_app` صلاحياته على قواعد `fcl_` بس.

**مشاكل اكتُشفت واتصلحت:**
- جلسات الـ Tenants كانت بتتخزن في الـ Central DB، واتحلت بـ `TenantAwareDatabaseSessionHandler`.
- ترتيب الـ Middleware كان بيخلي `auth` يشتغل قبل `ScopeSessions`، واتصلح.
- Regression خلّى كل صفحات الـ Tenant ترجع 404 على السيرفر الحقيقي، واتصلح.
- ثغرات npm في `tinypool`، واتحلت بـ npm override مؤقت.

**الاختبارات:** 74 test (73 passed، 1 skipped).

**القيود:** الـ Cache مش معزول لكل Tenant (مفيش Redis)، والـ Provisioning بيشتغل جوه الـ Web Request (Synchronous)، و 2FA مقفول.

## 4) Milestone 2 — Tenant Users & Permissions (`MILESTONE_02_TENANT_USERS_PERMISSIONS.md`)

**الهدف:** الـ Tenant Admin يدير الموظفين والأدوار والصلاحيات جوه شركته بأمان.

**اللي اتعمل:**
- صفحة `/employees`: بحث، فلاتر، إنشاء، تعديل، تفعيل/تعطيل، تحديد الأدوار. الموظف الجديد بيدخل فرع `MAIN` وبياخد Password مؤقت.
- **تعطيل الموظف** بيمسح جلساته ويغيّر الـ Remember Token ويمنعه من الدخول فورًا.
- صفحة `/roles`: إدارة الأدوار المخصصة.
- **7 صلاحيات:** `employees.view|create|update|deactivate` و `roles.view|manage|assign`.
- **دوران أساسيان:** `Tenant Admin` (كل الصلاحيات، محمي) و `Employee` (من غير صلاحيات).
- **قواعد منع التصعيد (`PrivilegeGuard`):**
  1. متقدرش تدّي صلاحية إنت مش عندك.
  2. متقدرش تعدل على حد أعلى منك.
  3. الـ Tenant Admin بس هو اللي يدّي دور Tenant Admin.
  4. متقدرش تعدل أدوارك أو تعطل نفسك.
  5. آخر Tenant Admin نشط محمي.

**مشكلة أمنية مهمة:** الطريقة الموثقة لدمج Stancl مع Spatie (تغيير Cache Key بس) **مش كفاية**. بيانات الصلاحيات المحملة في الذاكرة كانت بتفضل من Tenant لـ Tenant في نفس الـ Process، فموظف في شركة B ممكن ياخد صلاحية من شركة A لأن أرقام الأدوار بتتكرر. الحل: `PermissionCacheBootstrapper` بيعمل Reset كامل مع كل تبديل Tenant.

**الاختبارات:** 108 test (107 passed، 1 skipped).

**اللي اتعمل:**

## 6) Milestone 4 — Subscriptions, Seats & Billing (`MILESTONE_04_SUBSCRIPTIONS_BILLING.md`)

**الهدف:** نظام اشتراكات سنوية ومقاعد وفواتير يدوية.

> **مهم:** مفيش أي أسعار تجارية متسجلة. الأسعار والعملات بيدخلها الـ Platform Admin، والسياسات التجارية لسه **قرارات مفتوحة**.

**اللي اتعمل (في المنصة المركزية):**
- **الخطط (Plans):** اسم، عملة (بتتحدد مرة واحدة ومتتغيرش)، Base Fee، سعر المقعد. ينفع تتأرشف، ومفيش حذف.
- **تفعيل الاشتراك:** اختيار خطة + عدد مقاعد + تاريخ بداية → Preview → تأكيد.
- **التجديد:** بيفتح قبل الانتهاء بـ 30 يوم، ولو السعر اتغير لازم تأكيد صريح.
- **طلبات المقاعد:** موافقة أو رفض، مع عرض المبلغ المظبوط.
- **الفواتير والمدفوعات:** دفع جزئي مسموح، الدفع الزيادة ممنوع، والسجلات **Append-only** (متتعدلش ومتتمسحش).

**في صفحة الشركة:**
- صفحة `/subscription` بتعرض الخطة والمقاعد والفواتير، ومنها تطلب زيادة أو تقليل مقاعد.
- صلاحيتين جداد: `billing.view` و `billing.manage`.

**قواعد مهمة:**
- **الفلوس:** Integer Minor Units (يعني سنتات) + `brick/math`، **ممنوع Float**.
- **معادلة الـ Proration:** `المقاعد × سعر المقعد × الأيام المتبقية ÷ أيام المدة`، و Rounding **Half Up** مرة واحدة. السنين الكبيسة متحسوبة.
- **حالة الاشتراك محسوبة مش متخزنة:** Legacy / None / Active / Expired.
- الشركة اللي من غير اشتراك نشط تقدر تدخل وتشوف الإعدادات وصفحة الاشتراك بس، وباقي النظام مقفول.
- **منع الـ Race Conditions:** Named Lock في MySQL لكل شركة. اتجرب بـ 6 Processes على مقعدين فاضيين: اتنين نجحوا و 4 اترفضوا.
- **الشركات القديمة (Legacy):** من غير حد للمقاعد لحد ما يتفعلها اشتراك.

**اختيارات تقنية مؤقتة (مش قرارات تجارية):** مفيش Grace Period، والتجديد المتأخر بيبدأ من يوم التجديد (الفترة الفاضية مبتتحاسبش)، وفيه قائمة عملات مسموحة (EGP، USD، SAR، ...).

**مشكلة أمنية:** Livewire كان بيفتكر إن الـ Middleware اشتغل قبل كده جوه الـ Process الطويلة، فبيعدّي الفحوصات. الحل: `Livewire::flushState()` بعد كل Request.

**الاختبارات:** 280 test (279 passed، 1 skipped).

## 7) Milestone 5 — Support, Impersonation & Security (`MILESTONE_05_SUPPORT_IMPERSONATION_SECURITY.md`)

**الهدف:** دخول دعم فني مؤقت ومقيد ومسجل، ومراجعة أمنية شاملة.

**1. Platform Admin → Tenant Admin (Support Session):**
- **مقفولة افتراضيًا** (`SUPPORT_ACCESS_ENABLED=false`).
- محتاجة: سبب، Password الأدمن، وكود 2FA جديد.
- الانتقال من المركز للشركة بيتم بـ **Token لمرة واحدة**: مدته 60 ثانية بالكتير، مبعوت في POST (مش في الـ URL)، متخزن كـ Hash بس، ومربوط بشركة واحدة. لو اتبعت لشركة غلط بيتحرق.
- المدة **15 دقيقة**.
- كل الـ Tenant Admins بيوصلهم **إشعار** جوه النظام.
- **Banner** واضح بعداد تنازلي وزرار إنهاء.

**2. Tenant Admin → Employee (View as):**
- جوه نفس الشركة بس، بسبب و Password.
- ممنوع على نفسك، أو على Tenant Admin تاني، أو على حد صلاحياته زيك أو أعلى.
- **ممنوع الـ Impersonation المتداخل**.

**3. سياسة التقييد (Allowlist) على 3 مستويات (HTTP و Livewire و Gate):**
- **مسموح:** عرض الصفحات (GET) وشوية عمليات Livewire آمنة (بحث، فلاتر، صفحات).
- **ممنوع:** تغيير Passwords أو إيميلات، إدارة موظفين أو أدوار، طلبات مقاعد، فواتير، وأي حاجة مش في القائمة. **أي Feature جديدة (زي FCL) ممنوعة افتراضيًا.**

**4. الإنهاء التلقائي:** الجلسة بتخلص لو المدة خلصت، أو اتعملها Revoke، أو الشركة اتوقفت، أو الاشتراك خلص، أو الهدف اتعطل، أو الأدمن فقد صلاحيته.

**5. 2FA للـ Platform Admin:** TOTP و 8 Recovery Codes، متشفرة، ومحمية من الـ Replay، وفيه أمر `platform:reset-two-factor`. **اختيارية للوجين** وإجبارية لبدء جلسة دعم. واتشالت "Remember me" من لوجين المنصة.

**6. إصلاحات أمنية:**
- قفل مسارات رفع الملفات المؤقتة في Livewire (كانت بتشتغل برا سياق الشركة).
- قفل مسارات عرض ملفات الـ Local Disk.
- إضافة Security Headers.
- إصلاح ترتيب الـ Gate بحيث القيود تقدر ترفض صلاحيات Spatie.
- منع آخر Tenant Admin من مسح حسابه.

## 16) `fcl/OPERATIONAL_WORKFLOW.md` — رحلة الشحنة المصرية

```
قبل النظام: المستورد يعمل ACI في NAFEZA ← ACID بيطلع، ومستندات المصدّر عن طريق CargoX
───────────────────── جوه الـ IMPORT JOB ─────────────────────
1  الـ Documentation تستلم الـ Pre-Alert              [مؤكد]
2  نفس الموظف يفتح الـ Job، والـ ACID إجباري          [مؤكد]
3  هيكل الـ BLs (MBL / HBLs) والحاويات والأطراف
4  متابعة الرحلة: تغيير الـ ETA، والـ Arrival Notice
5  الوصول والتفريغ — لكل حاوية لوحدها
6  البيان الجمركي + الإفراج الجمركي  ┐
7  إفراج الخط / إذن التسليم (DO)     ├ بالتوازي ومستقلين [مؤكد]
8  جاهزية الميناء (لكل حاوية)         ┘
9  التسليم (رحلة أو أكتر، لكل حاوية): Gate-out ← POD
10 إرجاع الحاوية الفاضية — لكل حاوية
11 الإغلاق التشغيلي        12 الإغلاق المالي  (منفصلين) [مؤكد]
```

- **جدول مسؤوليات (RACI)** لكل مرحلة بين Documentation و Operations و Customs و Finance. المؤكد منه بس إن الـ Documentation بتستلم وبتفتح، وإن فيه فريق جمارك داخلي.
- **الفرق بين المسارين:** في حالة الـ **Origin Agent** غالبًا فيه MBL + HBL. في حالة الـ **Direct Line** مفيش Agent، والـ MBL بس.
- **حالة الـ Consolidation:** كل HBL ليه ACID، وفيه ACID للـ Master.
- **جدول الاستثناءات:** مستند ناقص، حاوية موصلتش، فحص جمركي، الجمرك أفرج بس الـ DO مش جاهز، BL أصلي ضايع، الـ ETA اتغير، تسليم جزئي، تأخير في إرجاع الحاوية، بضاعة خطرة أو مبردة.
- **حاجات ممنوع النظام يكتبها كحقيقة:** مدد التخليص، أيام السماح، أسماء حالات NAFEZA، قائمة مستندات NAFEZA كقائمة للـ Pre-Alert، وصيغة الـ ACID.

## 17) `fcl/DOMAIN_MODEL.md` — الكيانات والعلاقات

**التوزيع:** `fcl_central` فيه الشركات والاشتراكات والدعم الفني، **ومفيش فيه أي بيانات FCL**. قاعدة كل شركة فيها: `parties`، `import_jobs`، `job_parties`، `aci_records`، `bills_of_lading`، `bl_containers`، `containers`، والأحداث والـ Audit، وبعدين المهام والمستندات والجمارك والإفراج والتسليم والمصاريف.

**الكيانات الأساسية وقواعدها الثابتة:**
- **Import Job:**
  - لازم يكون ليها **ACID واحد على الأقل** طول الوقت.
  - **فرع أساسي واحد**.
  - `created_by` **مبيتغيرش أبدًا**.
  - **مفيش `draft`**.
  - الـ ETA بيتسجل له تاريخ كامل.
- **Party / Job Party:** طرف واحد للشركة كلها، وليه أدوار مختلفة لكل Job (العميل ممكن يكون هو المستورد وهو المستلم).
- **ACI Record:**
  - String متنضف (من غير مسافات).
  - ممنوع يتكرر في نفس الـ Job.
  - التكرار بين Jobs مختلفة = تحذير.
  - **ممنوع يتسمى "verified"**.
- **Bill of Lading:** نوعين Master و House. الـ HBL **مش إجباري**، والـ HBL أبوه لازم يكون MBL في نفس الـ Job.
- **Container:**
  - التحقق بـ ISO 6346.
  - رقمها فريد **جوه الـ Job بس** (لأن الحاويات بتتعاد).
  - حالتها خاصة بيها لوحدها.
- **Events:** Append-only. الـ Audit بيجاوب "مين غيّر إيه"، والـ Events بتجاوب "إيه اللي حصل للشحنة".

**جدول "افتراضات خطيرة":** Job لكل BL، ACID واحد للـ Job، ACID كرقم، BL واحد لكل حاوية، Status واحدة، "اتفرج عنه = جاهز للتسليم"، "اتسلم = اتقفل"، Vessel + Voyage كمفتاح... **كلها غلط**، والملف بيشرح البديل الصح لكل واحدة.

## 20) البحث الأول R1 — `research/01-global-fcl-research.md` (عالمي، إنجليزي)

- **مقارنة أنظمة تجارية:** CargoWise و Magaya و GoFreight و Descartes. **الدرس:** مساحة شغل واحدة للشحنة، بس الكيانات (Booking، BL، حاوية، أحداث، مستندات، مالية) منفصلة. وتفاصيل الـ Tenancy الداخلية بتاعتهم **مش معلنة**.
- **المعايير:** DCSA (Booking، BL، Arrival Notice، Track & Trace، والـ Release لسه بيتعمل)، و ISO 6346 للحاويات، و UN/LOCODE للموانئ، و EDIFACT كـ Adapter بس.
- **المعمارية:** خلّي **Database لكل Tenant**، و `fcl_central` يفضل Control Plane. كل Queue Job لازم يكون إما للشركة أو مركزي، و**يفشل** لو مش عارف هو تبع مين.

- **الـ API:** الـ Livewire والـ API يستخدموا **نفس الـ Actions**، و **ممنوع** تقبل `tenant_id` من الطلب.
- **الأمان:** الـ Impersonation ممنوع من الكتابة في FCL، والـ Audit يسجل الفاعل الأصلي والفعلي، ومفيش بيانات كروت دفع.
- **خطة M1 → M6** واستراتيجية اختبارات (عزل، Queues، ملفات، تزامن).
- **الجملة المحورية:** *"ابني نظام تشغيل للشحن، مش Spreadsheet رقمي"*. الـ Job مساحة شغل، والـ BL مستند نقل، والحاوية معدّة، والحدث حقيقة تاريخية، والإفراج بوابة، والمصروف حقيقة مالية.

> **ملحوظة:** بعض توصيات R1 اترفضت بقرارات صاحب المشروع (Draft Jobs، و `acid_number` كعمود، و API في M1).

## 21) البحث التاني R2 — `research/02-egypt-operations-research.md` (مصر، عربي)

- **أهم إضافة:** الـ ACID **مينفعش** يكون عمود واحد. في الـ Consolidation كل HBL ليه ACID، وفيه ACID للـ Master.
- **4 حقايق أساسية:**
  1. الـ ACI عملية **قبل الشحن** (48 ساعة قبل الشحن، ودي غير مهلة الـ Manifest).
  2. NAFEZA بتتعامل مع الـ ACID بدورة حياة (Verify و Lock).
  3. الـ Freight Forwarder ليه دور في MBL/HBL.
  4. الإفراج الجمركي ≠ إفراج الخط ≠ جاهزية الميناء ≠ التسليم.
- **رحلة يومية مفصلة** من الـ Pre-Alert لحد إرجاع الحاوية الفاضية، مع أمثلة من Hapag-Lloyd و CMA CGM و Maersk، وموانئ إسكندرية ودمياط.
- **مستندات الـ ACI المعتادة:** Commercial Invoice، Packing List، **نسخة** من الـ BL، شهادة المنشأ، وشهادات حسب نوع البضاعة. وحد 5 MB للمستند (ده قاعدة لرفع ملفات الـ ACI، **مش** حد التخزين في نظامنا).
- **سيناريوهات:** Origin Agent، و Direct Line، و Consolidated، وحاويات متعددة بحالات مختلفة.
- **Free Time والغرامات:** **ممنوع** `free_days = 7` في الكود. لازم تبقى قيمة ليها مصدر ومتراجعة.
- **اقتراح شاشات:** Jobs Inbox بفلاتر، و Job Workspace بـ Tabs، و Overview بيجاوب "إيه اللي موقف الشحنة دلوقتي؟".
- **أسئلة لازم تتسأل للموظفين الحقيقيين**، وقائمة بالملفات المطلوبة من الشركة.
- **القرار النهائي:** *"إنت جاهز تبدأ FCL M1 Specification، مش جاهز تقول لـ Claude ابني كل FCL"*. الخطوة الجاية جلسة مع Operations وملفات حقيقية، مش بحث نظري تالت.

> **ملحوظة:** R2 كان مقترح Draft Job ودورة حياة ACI جوه التطبيق، وصاحب المشروع رفض الاتنين.
